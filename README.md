# dsht

**给 [dsh](https://github.com/deepseek-ai/deepseek-harness) 做的一个终端界面。**

主屏只有输入和输出；一个键调出菜单，用方向键选。目标是让不写代码的人也能用 agent。

```
 dsht  报告分析                                     Esc 停止 · / 命令
──────────────────────────────────────────────────────────────────
 > 帮我看看这个报告

 = 好的，我先读一下。
 ● 工具 read  {"file_path":"reports/2026-q3.md"}
 ∗ 思考 先看目录结构，再挑重点章节读…
 = 报告主要讲了三点：…

   1. 营收同比增长 12%
   2. 成本上升主要来自人力
──────────────────────────────────────────────────────────────────
╭────────────────────────────────────────────────────────────────╮
│ > /                                                           │
╰────────────────────────────────────────────────────────────────╯
 173 轮 · 2260 步 · 208 tok/s · 缓存 99.5%                    ○ 空闲
```

> **状态：阶段 2 已完成**——发消息、流式回复、翻页、中文输入法、历史分页、
> **审批 / 提问 / 计划评审面板**、命令面板（含参数选项）、状态行用量数据，都能用了。
> **还差阶段 3：`Esc` 菜单**（会话 / 模型 / 设置 / 退出）。
> 在那之前，`Esc` 在 agent 运行时是「停止」。
>
> 自己试：`npm install` 然后 `npm start`。

## 为什么做这个

dsh 官方只有浏览器界面。第三方终端界面（dsh-TUI）操作靠大量斜杠命令和快捷键，**必须先记住命令才用得出来**。

这个项目要的是**游戏暂停菜单**那种逻辑 —— 每个人都玩过游戏，不需要学。

---

## 它是怎么工作的

dsht 是一个**独立的 Node 程序**，通过 dsh 官方的 HTTP + WebSocket API 连接到一个 `dsh web` 进程。

**它不改 dsh 一行代码，不装插件，不动配置。** 本质上它就是一个"另一种浏览器"。

```
dsh web（后端）  ←── 官方 API ──→  dsht（终端界面）
```

细节见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

### 看效果 / 改外观

界面是「代码即真相」——所有预览脚本都调用**真实**的渲染函数，
所以你看到的就是实际的样子，不存在「文档跟界面不一致」。

| 命令 | 看什么 |
|---|---|
| `npm run preview:ui` | **一次看清三种面板**（事件面板、命令面板、计划全文整屏） |
| `npm run preview:ui -- --compare` | 同一段对话「带颜色 vs 去掉颜色」并排看 —— 回答「无色还读得出来吗」 |
| `npm run preview:ui -- --no-color` | 整个预览去掉颜色 |
| `npm run palette:preview` | 完整界面长什么样（配色视角） |
| `npm run palette` | 当前配色下每个语义令牌是什么颜色 |
| `npm run markers` | 行首标记的候选清单 + **宽度自检尺子** |
| `npm run markers:write` | 重新生成 `docs/MARKERS.md` |
| `npm run symbols` | 挑符号用的横向对照表（码点、宽度） |
| `npm run contrast` | 配色对比度实测（按 Windows Terminal 默认主题算） |

### 查 dsh 的命令 / 诊断

| 命令 | 干什么 | 会不会新建会话 |
|---|---|---|
| `npm run commands` | 列出 dsh 当前支持的全部斜杠命令（问服务端要，不是我编的） | 不会（复用探针会话） |
| `npm run commands:try` | 真跑一遍每个命令，看它们实际返回什么 | 不会（复用同一个探针会话） |
| `npm run timing` | 量一下「起服务 → 连接 → 打开会话」各阶段各花多久 | 不会 |
| `npm run projections` | dump 一个会话的**全部投影**（状态行的数字、权限预设都是从这儿来的） | 不会 |
| `npm run width:check` | 拿 111 万个码点逐点核对列宽算法 | 不会 |

> 起一个 dsh web 大约要 **8～10 秒**（插件加载 + 索引），所以这几个命令天然不会秒回。
> 它是**在等 dsh**，不是卡住了 —— 想确认的话跑 `npm run timing`，它会打印每阶段的耗时。
>
> 探针最多只占**一个**会话（id 记在 `probe/.probe-session-id`，已 gitignore），
> 不会在你的会话列表里积垃圾。
>
> **本项目不碰 `~/.dsh/sessions` 里的会话文件**（红线之一）：会话数据只走官方 API。
> 要清理历史会话请用 dsh 自己的方式，本项目不提供这类命令。

### 检查代码

`npm test` 按顺序跑三层，任何一层挂了后面的就不跑：

| 命令 | 检查什么 |
|---|---|
| `npm run typecheck` | 类型。**包括两个 `.mjs`**（传输层），它们的声明在 `src/*.d.mts` |
| `tsx tests/source-hygiene.test.ts` | 源码里有没有混进裸控制字符（见下） |
| `tsx tests/*.test.ts(x)` | 行为 |

关于卫生检查：本项目多次出现「想在源码里写 `\n`，结果写进去一个真换行」的错，
成因都是同一个 —— **用某种脚本语言的字符串去生成源码**，中间那一层先把自己的
转义语法解释了一遍。所以规矩是：写源码只走字面量通道（编辑工具，或 bash 的
`cat <<'EOF'`），不要在字符串里再加一层反斜杠。真出了手滑也不用怕，
卫生检查会直接指出文件第几行第几列。
