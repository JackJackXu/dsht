# dsht 开发计划

> **一句话**：给 dsh 做一个能长期用的终端界面 —— 平时就是聊天，按 Esc 弹出游戏式的菜单。
>
> 立项：2026-09-13 ｜ 状态：阶段 2 进行中（能聊天了；审批面板与 Esc 菜单待做）

---

## 零、这个项目是什么，为什么这么做

### 要解决的问题

dsh 官方只有浏览器界面。现有的第三方终端界面（dsh-TUI）操作靠大量斜杠命令和快捷键，**必须先记住命令才用得出来**，对非程序员不友好。

我们要的是**游戏暂停菜单**那种逻辑：

- 主画面 = 游戏本体（聊天，纯输入输出）
- 按一个键 = 暂停，弹出菜单
- 方向键选、Enter 进、Esc 退

**每个人都玩过游戏，这个操作模型不需要学。**

### 为什么这条路走得通

dsh 的前后端是分开的，官方 API（Typert API Gateway）是正式、公开、已发布的。官方 web UI 只是它的**一个客户端**。

我们做的是第二个客户端。详细证据见 [RESEARCH.md](RESEARCH.md)。

**还有个额外好处**：官方 Electron 桌面版走的是同一套路（同一套前端 + 自己的传输层），我们做的是"终端版"，性质完全一样——不是歪门邪道。

## 一、最终做出来是什么样

### 平常就是聊天

```
┌──────────────────────────────────────────────┐
│  > 帮我看看这个报告                            │
│                                              │
│  = 好的，我先读一下……                          │
│                                              │
├──────────────────────────────────────────────┤
│ > 在这里打字……                                │
└──────────────────────────────────────────────┘
```

### 按 Esc 弹出菜单

```
┌──────────────────────────────────────────────┐
│  > 帮我看看这个报告                            │
│  = 好的，我先读一下……                          │
├───────────── 菜单 ───────────────────────────┤
│    > 会话        新建 / 切换 / 恢复            │
│      模型        换模型                       │
│      设置        主题 / 语言 / 权限            │
│      退出                                     │
│                                              │
│    ↑↓ 选择    Enter 进入    Esc 返回           │
└──────────────────────────────────────────────┘
```

### 操作一览

| 按键 | 作用 |
|---|---|
| 打字 + Enter | 发送 |
| `/` | 照旧，调出原来的命令补全 |
| **Esc** | 打开菜单（输入框有内容时先清空，不误触） |
| 菜单里 `↑↓` / `Enter` / `Esc` | 选 / 进 / 退 |
| 子菜单里 `←` | 回上一层 |

### 主屏显示策略（用户已定：方案 C）

工具调用、思考过程**默认折叠**，只显示最终回复；按一个键展开看细节。

## 二、技术方案（三层）

```
┌──────────────────────────────────────────┐
│ 第 3 层：界面（我们自己写）                 │
│   Ink 渲染 · 主屏 · Esc 菜单 · 输入框       │
├──────────────────────────────────────────┤
│ 第 2 层：载体（我们自己写，但很小）          │
│   globalThis.__DSH_TRANSPORT__            │
│   = { fetch, openStream }                 │
├──────────────────────────────────────────┤
│ 第 1 层：数据（官方提供，我们一行不写）      │
│   @deepseek-ai/dsh-api-* 客户端库          │
│   会话 / 模型 / 设置 / 审批 / 提问          │
└──────────────────────────────────────────┘
                    ↕ HTTP POST + WebSocket
              dsh web（后端进程，独立运行）
```

**关键点：第 1 层全免费。** 会话创建、恢复、发消息、看历史、实时状态、审批、提问，全部由官方包提供。我们只管画。

## 四、如果阶段 1 失败：备用方案

按优先级：

1. **进程内挂官方包** —— 自己写一个 dsh app bundle + 自己的界面。能拿到全部能力，但要啃官方内部接口，dsh 一升级容易坏。
2. **给官方 web 客户端写插件** —— 稳，但是网页不是终端。

**不管走哪条，操作手感和红线都不变。**

---

## 五、红线（绝不越界）

1. ❌ 不修改 dsh 安装目录里的任何文件
2. ❌ 不往任何 profile 里装插件
3. ❌ 不动 `~/.dsh` 的配置和插件
4. ❌ 不读写 `~/.dsh/sessions` 里的会话文件（会话数据一律走官方接口）
5. ❌ 不用任何第三方 dsh 前端（dsh-TUI 等）的代码
6. ✅ 每一步做完给出验证方法，用户不点头不往下走

**本质：我们的程序就是一个"另一种浏览器"。** 浏览器能干的它才能干，浏览器干不了的它也干不了。
